## 0. How to read this file

- Scope: every image, brand, creative-brief, prompt, rendering and visual-QA rule merged from the sources listed in section 15. Content, strategy and research rules live in `content-rules.md`, not here.
- Every rule is tagged with its source, e.g. [v36] or [source: brand-source-of-truth-v36.md]. A rule appears in exactly one of the two files; cross-references name the other file instead of repeating the rule.
- Do not invent rules, numbers or claims. Where a source still says Inter / DM Sans / #10B981, the text is carried verbatim with a [STALE — superseded by verified website tokens 2026-11-24] note. Nothing here silently rewrites a source.
- Conflicts are kept, not resolved: each conflicting rule is carried with a CONFLICT note naming both sources. The owner decides later.
- Statuses used throughout: PASS / REJECT / BLOCKED / NOT_VERIFIED / RENDERED_REQUIRES_INDEPENDENT_VISUAL_QA / HANDOFF_READY (never HANDOFF_DONE without verified remote completion).

## 9. Prompt engineering and render spec

9.1. Stage D — prompt engineering: only from a PASS brief, produce two artifacts. (1) `render_spec.json`: exact text, typography families and weights, layout geometry, colour tokens, spacing, logo binary path + hash, output metadata. This is the authoritative source for deterministic text and logo compositing. (2) `image_prompt.md`: art direction, buyer context, desired visual storytelling, layout zones, image subject and treatment, lighting/texture if appropriate, visual exclusions, brand constraints and non-text image elements. Include explicit negative prompt for invented logos, unreadable text, extra UI, watermarks, fake badges, unsupported metrics, irrelevant stock imagery. Never rely on an image generator to reproduce critical small text or official logo accurately: composite them from verified assets. [source: content-to-creative-brief-v21.md]
