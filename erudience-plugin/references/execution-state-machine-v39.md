# Erudience v3.9 — enforced production workflow

Authoritative controller: `scripts/production_controller_v39.py`. All new content-to-image requests MUST use this controller, not the legacy seven-slot `workflow_engine.py`, legacy `production_gate.py`, or direct `image_gen` as a delivery path. Legacy tools are historical or draft-only and do not certify production readiness.

Stages: SOURCES → RESEARCH → STRATEGY → CONTENT → CONTENT_QA → BRIEF → BRIEF_QA → RENDER → TECH_QA → VISUAL_QA → CONTENT_MATCH_QA → BRAND_QA → DELIVERY. The controller accepts one content item and requires stages in order. `CONTENT` locks topic and caption; `BRIEF` must bind to the content artifact hash and include the exact poster text; `RENDER` must bind to the brief hash and real image bytes; all image reviewers must bind to both the image hash and brief hash. No stage may be skipped.

Failure transition: SOURCES→SOURCES, RESEARCH→RESEARCH, STRATEGY→STRATEGY, CONTENT/CONTENT_QA→CONTENT, BRIEF/BRIEF_QA→BRIEF, RENDER/TECH_QA/VISUAL_QA→RENDER, CONTENT_MATCH_QA/BRAND_QA→BRIEF, DELIVERY→DELIVERY. On failure, all receipts from repair target onward are invalidated. Revision cap 3; fourth failure yields BLOCKED. A revision must actually be executed by the producer; the controller does not invent revised content or call an AI model by itself.

Owner's current website-first brand profile v3.8 overrides legacy Sora-only and logo-required rules: Inter headings, DM Sans body, website palette, Erudience name and erudience.com footer. Logo optional. An authentic logo may be used only if verified. Educational content uses a subtle CTA, no unsupported performance claims. Six-step content must use a renderer that can display all six steps or the brief must be deliberately restructured and reapproved; silently dropping a step is forbidden.

Reviewers must inspect actual rendered pixels and mobile-size legibility; record observations, exact poster topic, brand assessment and reviewer identity. Controller validates receipt structure and binding but **cannot cryptographically authenticate reviewer identity or establish semantic correctness**. A reviewer PASS without real independent inspection is prohibited; missing runtime reviewer means BLOCKED. Do not claim automatic end-to-end success from unit tests alone.

Direct image generation is allowed only for explicitly labelled exploration, never as an approved output without running all stages. `DELIVERY` status READY_FOR_OWNER_REVIEW does not imply publishing. No Social OS/LinkedIn/database writes or scheduler actions. Any non-PASS is reported with failure reason and exact return stage.

Run: `python scripts/production_controller_v39.py init --state job.json --content-id <id> --topic <topic>`; for each stage create JSON artifact and call `pass --state job.json --stage STAGE --artifact artifact.json` with `--reviewer` and `--producer` for reviewer stages, and `--source-verified` for source/research. On failure use `fail --state job.json --stage STAGE --reason 'reason'`; inspect `status --state job.json`. Use file persistence per job; concurrent writers require an external lock/transactional store not provided here.
