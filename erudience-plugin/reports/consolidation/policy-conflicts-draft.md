## C17 — Font verification: which families, verified when?

- **Gate chain (live mode):** verifies only the heading family binary (`for family in (BRAND['heading'],)` in `scripts/gate_chain_v41.py`) — body font binary is never verified at build time (audit §2 gap 3). In fixture mode, only `font_provenance[heading]` presence is required.
- **`scripts/website_brand_v38.py`:** requires both `font_heading_sha256` and `font_body_sha256` (`FONT_PROVENANCE_MISSING` if either absent).
- **`scripts/website_render_v38.py`:** verifies both font files + SHA256 at render time (`FONT_FILE_UNVERIFIED:heading_font_file/body_font_file`).
- **`scripts/render_poster.py`:** requires 4 font files on the CLI (Inter bold/semibold, DM Sans regular/medium) and raises if any path is missing.
- **`scripts/brand_render_v37.py`:** requires Sora regular + bold files with SHA256 + source (`UNVERIFIED_SORA_REGULAR` / `UNVERIFIED_SORA_BOLD`).
- **`scripts/brief_prompt_gate.py`:** requires only a boolean `font_files_verified` in the prompt spec — no family, path, or hash.
- **Status: UNRESOLVED.** The five mechanisms verify different families, at different stages, with different evidence (file+SHA vs boolean). Which families must be verified, and at plan time vs build time vs render time, depends on C1 and has no single answer in the files read.
